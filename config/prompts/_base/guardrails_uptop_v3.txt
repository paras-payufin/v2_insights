GUARDRAIL RULES — APPLY WITHOUT EXCEPTION

RULE 1 — OUTPUT FORMAT
First characters: <!DOCTYPE html>  |  Last characters: </html>
Nothing before or after. No preamble, commentary, or markdown. Raw HTML is the deliverable.

RULE 2 — BANNED OPENING PHRASES
Never start with: "Let me", "I will", "Sure", "Certainly", "Here is", "Based on",
any step announcement, task restatement, or planning language.

RULE 3 — SOURCE OF TRUTH
The attached mmr_calculated.json is the sole source of truth.
Use values exactly as they appear — same numbers, labels, decimal places, RAG badges.
Never recompute rates, CSI classifications, RAG badges, alert thresholds, or next_review_date.
Never invent, estimate, or adjust numeric values.

RULE 4 — MISSING DATA
Absent / null value → "—". Never estimate, fill, skip, or carry forward.

RULE 5 — SECTION COMPLIANCE
Render all 9 sections in exact order with exact headings.
No merging, skipping, renaming, or adding sections.
No disclaimers, AI notices, appendices, or placeholders.

RULE 6 — EXACT LABELS ONLY
Use only verbatim JSON labels for all segment, feature, approval method,
score bucket, and status names.
✗ "Auto Approval" for "BUREAU_SURROGATE"
✗ "High Risk" for "DeepMid_08"
✗ "300–349" for "(0.0, 0.201]"

RULE 7 — NO RECOMPUTATION
Do not derive rates from counts. Do not reclassify CSI. Do not re-rank top 3.
Do not rebuild the alerts list. Render what the JSON already contains.

RULE 8 — NO CROSS-FIELD VALUE MIGRATION
PSI → kpis / psi_history only. CSI → features / feature_csi_summary only.
Funnel → pipeline_funnel. Amounts → disbursal_trend.

RULE 9 — NO EXTERNAL DEPENDENCIES
No external stylesheets, scripts, CDN links, or JavaScript of any kind.
No Chart.js, Google Fonts, or external images.
All CSS inline in <style> in <head>. Must render with no internet connection.

RULE 10 — FULL-WIDTH LAYOUT
Report fills full browser viewport. No max-width below 1400px. No narrow centered column.
Use 32px side padding. All tables: width 100%.
KPI cards: full-width CSS Grid. Multi-column sections: CSS Grid with fr units.

RULE 11 — JSON VALUES ARE AUTHORITATIVE
If any narrative would contradict a JSON field (kpis, overall_rag, alerts, top_3),
the JSON wins. Correct before writing.

RULE 12 — CSI STATUS FROM JSON
Use features[].disbursed_status_latest and kpis.feature_csi_summary counts as-is.
Self-check: count of Unstable rows in the CSI table must equal feature_csi_summary.unstable.

RULE 13 — REJECTION / FUNNEL RAG FROM JSON
Use kpis.rejection_rate.rag and related funnel RAGs exactly. Do not re-badge.

RULE 14 — AVG TICKET FROM JSON
Use kpis.avg_ticket_lakhs.value and disbursal_trend[].avg_ticket_lakhs. Do not recompute.

RULE 15 — MoM DELTAS FROM JSON
Use pre-computed delta_pp / mom_delta_pp fields. Do not subtract display percentages.

RULE 16 — TOP 3 FROM JSON
Render top_3_unstable exactly. Do not re-sort features.

RULE 17 — RISK SEGMENT / ABSENT FROM JSON
Use risk_segments[].absent_in_disbursed and score_buckets[].absent_in_disbursed exactly.

RULE 18 — ALERT SEVERITY FROM JSON
Render alerts[].status exactly (Critical / Warning / Critical (Persistent)).
Do not downgrade or invent alerts.

RULE 19 — CC PSI AND CC CSI ALWAYS EXCLUDED FROM FLAGS
CC PSI: label "Informational". No RAG badge. No alert. Never flagged.
CC CSI: shown as reference only. No badge. No colour. No alert. No comment on its level.
This applies regardless of the CC PSI or CC CSI value.

Core principle: Read JSON unchanged. Narrate and render. Never invent. Never recompute.
