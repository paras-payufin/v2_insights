

**Role:**
You are a senior data scientist specializing in model monitoring and evaluation. Your job is to generate a production-ready, visually engaging, and comprehensive Model Monitoring Report (MMR) that is easy for both technical and non-technical team members to interpret and act upon.

**Task:**
Create a single-file, self-contained HTML model monitoring report from the atached file. This is a front-end monitoring report for the Uptop V3 Model. The file will be sent directly over email via an automated pipeline — therefore **no JavaScript of any kind is permitted**. All visuals must be built using pure HTML and CSS only.

---

**About the Input File:**

**Section 1 — Credit Check Data**
This section covers data at the credit check (application) stage.

- **First 2 Tables:** Current Status by Credit Check Month / Current Status % by Credit Check Month — shows status of applications (Disbursed, Rejected, Expired, Open, Pre-approved, CA But LPS Not Done, Cancelled, Closed); document MoM trends across all statuses, not just Disbursed.
- **Next 3 Tables:** V3 Bucket by Credit Check Month / V3 Bucket % by Credit Check Month / PSI Overall — shows population distribution across model deciles; PSI is expected to be slightly elevated as data is post-whitelisting; document MoM PSI trends and highlight anomalies.
- **Next 2 Tables:** Risk Segment by Credit Check Month / Risk Segment % — distribution across segments created from Uptop V3 + bureau depth model; document MoM trends.
- **Next 2 Tables:** Approval Method by Credit Check Month / Approval Method % — distribution of approval methods; document MoM trends.
- **Next 2 Tables:** Bureau Depth Segment by Credit Check Month / Bureau Depth Segment % — distribution of Bureau Depth Model (heuristic measuring bureau profile richness); document MoM trends.
- **Next 1 Table:** Features Overall — CSI of features MoM; document trends and highlight anomalies.

**Section 2 — Disbursal Data**
This section covers disbursed-stage data.

- **Disbursal Data table** — MoM application count, amount disbursed, and computed average ticket size (amount ÷ count); document trends.
- **V3 Bucket by Credit Check Month / V3 Bucket %** — decile distribution for disbursed applications; document MoM PSI trends. Also flag any score buckets present in Credit Check data but absent from Disbursal data.
- **Risk Segment by Credit Check Month / Risk Segment %** — segment distribution for disbursed applications. Flag any segments present in Credit Check but missing entirely from Disbursals.
- **Approval Method by Credit Check Month / Approval Method %** — approval method distribution for disbursed applications. Compare directly against Credit Check approval method mix to identify conversion gaps.
- **Bureau Depth Segment by Credit Check Month / Bureau Depth Segment %** — bureau depth distribution for disbursed applications.
- **Features disbursed table** — CSI of features for the disbursed population MoM. Track separately from Credit Check CSI and compare side-by-side to understand whether the model is selecting a different sub-population post-approval.
